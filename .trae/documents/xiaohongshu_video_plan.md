# 小红书视频处理功能实现计划

## 1. 需求分析

用户希望在 LLM Wiki 中增加处理小红书视频的能力，能够提取视频中的原始内容并转换为 Markdown 格式，以便整合到知识库中。

## 2. 现有架构分析

### 现有 ingest 操作流程

1. 确定待处理资料（URL/文本/文件）
2. 保存原始资料
3. 阅读并提取核心信息
4. 与用户讨论（可选）
5. 创建来源摘要页
6. 更新实体页和概念页
7. 更新主题页（如需）
8. 更新 index.md、overview\.md
9. 追加 log.md
10. 输出总结

### 现有目录结构

```
~/llm-wiki/
├── raw/                    # 原始资料（不可变）
│   ├── articles/           # 文章
│   ├── papers/             # 论文
│   ├── books/              # 书籍
│   ├── notes/              # 笔记
│   └── assets/             # 资源
└── wiki/                   # LLM 维护的 Wiki
    ├── index.md            # 内容目录
    ├── log.md              # 操作日志
    ├── overview.md         # 整体概览
    ├── entities/           # 实体页
    ├── concepts/           # 概念页
    ├── topics/             # 主题页
    ├── sources/            # 来源摘要
    └── solutions/          # 经验文档
```

## 3. 实现计划

### 3.1 扩展目录结构

在 `raw/` 目录下添加 `videos/` 子目录，用于存放小红书视频及其元数据：

```
~/llm-wiki/
├── raw/
│   ├── ...
│   ├── videos/            # 视频资料
│   │   └── xiaohongshu/   # 小红书视频
└── wiki/
    ├── ...
```

### 3.2 扩展 ingest 操作

1. **识别小红书视频链接**：

   * 支持识别小红书视频 URL（如 `https://www.xiaohongshu.com/video/...`）

   * 支持识别小红书分享链接

2. **视频内容获取**：

   * 利用适当的工具下载小红书视频

   * 提取视频中的文本内容（标题、描述、标签等）

   * 提取视频中的关键帧或截图

3. **内容处理**：

   * 分析视频内容，提取核心要点

   * 转换为结构化的 Markdown 格式

   * 保留原始视频的元数据

4. **整合到 Wiki**：

   * 创建来源摘要页（`wiki/sources/YYYY-MM-DD-小红书视频标题.md`）

   * 提取并更新相关实体和概念页

   * 更新索引和概览

### 3.3 技术实现细节

1. **视频下载**：

   * 使用适当的方法获取小红书视频内容

   * 保存视频到 `raw/videos/xiaohongshu/` 目录

2. **内容提取**：

   * 提取视频标题、描述、发布时间、作者信息

   * 提取视频中的文字内容（如字幕、屏幕文字）

   * 提取视频中的关键信息和要点

3. **Markdown 转换**：

   * 创建标准的来源摘要页格式

   * 包含视频元数据、核心要点、关键引用等

   * 添加视频截图或链接

4. **流程集成**：

   * 将小红书视频处理集成到现有的 ingest 工作流中

   * 确保与其他资料类型的处理保持一致

## 6. 风险与应对

* **视频获取限制**：小红书可能有访问限制，需要处理可能的访问失败情况

* **内容提取质量**：视频内容提取可能不够准确，需要人工审核机制

* **文件大小**：视频文件可能较大，需要考虑存储和处理性能
